# Golden harness audit, 2026-10-29 (prompt set v1.1 pass)

Scope: `prompts.jsonl`, both fixtures, both run-A candidates,
`gen_golden.py`, `compare.py`. Method: field-by-field record audit
plus source read. This note is the evidence list; fixes landed in
the same commit where they were in scope.

## What is complete

- Both fixtures (`tinyllama-1.1b-chat-v1.0.Q4_K_M`,
  `qwen2.5-1.5b-q4km`) hold exactly the 15 v1.0 prompt ids: none
  missing, none extra. Both run-A candidate files do too.
- Every record in both fixtures has the same field set: `id`,
  `category`, `prompt`, `prompt_token_ids`, `completion_token_ids`,
  `completion_text`, `ended_with_eos`. Prompt token ids are present
  for every prompt, so prompt tokenization is pinned, not just
  completions.
- Both fixtures' meta `prompts_sha256` matched the v1.0
  `prompts.jsonl` at audit time (before the v1.1 additions below),
  and the meta binds model SHA-256, model size, llama.cpp version,
  and decoding flags. No silent drift.
- `compare.py` does compare completion token ids exactly: the
  `token-identical` verdict is full list equality (ids, order,
  length), and prompt tokenization divergence is reported per
  prompt.

## Gaps found

1. **No probability or top-k data anywhere in the fixtures.**
   `gen_golden.py` requests `n_probs=1` from llama-server, which
   returns only the sampled token's own probability per step, and
   `extract_record` then discards even that: records keep the id
   only. So no fixture can answer "how concentrated was the
   reference here" or "what was the runner-up". Run B's diagnosis
   turned exactly on top-5 mass (reference top-5 = 0.62 of the
   probability, ours = 1.6e-4) and had to capture it ad hoc with
   `n_probs=5` outside the harness. Fixing this means raising
   `n_probs` in `gen_golden.py` and storing per-step top-k in the
   record; not done in this pass because it changes every fixture
   and must land with a full regeneration on the server.
2. **Completions are budget-truncated, not complete generations.**
   The cap is `n_predict=64`. TinyLlama: 15 of 15 records end at
   the cap (`ended_with_eos` false). Qwen2.5: 13 of 15 (only
   `arithmetic_add`, 30 tokens, and `code_python`, 47, stop on
   EOS). The fixtures pin token trajectories, which is what the
   differ needs, but no TinyLlama record exercises a natural stop,
   so an engine that never emits EOS correctly still passes all
   15 TinyLlama records; only Qwen's two EOS records can catch
   that defect class.
3. **`compare.py` non-strict exit code passes `text-identical`.**
   Without `--strict`, a candidate whose ids diverge but whose
   text matches exits 0. At temperature 0 that is a tokenizer or
   trajectory defect being waved through; the README documents
   this, but any caller that forgets `--strict` gets a green
   checkmark on a non-verified run. Also: `compare.py` never
   compares `ended_with_eos`, and it compares candidate prompt
   ids against golden but never the prompt text itself.
4. **v1.0 prompt coverage gaps for the divergence hunt** (fixed by
   addition in this pass, references pending, see
   PENDING-REFERENCES.md): no second strong-factual first-token
   probe (Run B's case was `factual_capital` on Glimmer; the
   fixture models had no analogue of their own), no prompt designed
   to force a long decode (existing records reach 64 tokens only
   because the cap allows it, not by design), no number-formatting
   prompt (the arithmetic prompts carry digits in the prompt
   already; nothing exercises word-to-digit assembly), and no
   punctuation/contraction prompt (the accented prompts exercise
   UTF-8 byte pieces, not apostrophe merges, the tokenizer's known
   trap area).
5. **Determinism of the reference was a claim, not a check.**
   README.md records byte-for-byte regeneration as verified for
   TinyLlama only, and no script existed to re-run that check on a
   new model or prompt set. Fixed in this pass:
   `determinism_check.py`.
6. **Cosmetic:** `compare.py`'s docstring says fixtures are
   "written by gen_golden.sh"; the generator is `gen_golden.py`.
   Left as-is in this pass to keep the diff to one concern; worth
   a one-line fix in any later touch of that file.

## Changes in this pass

- `prompts.jsonl`: prompt set v1.1, four prompts added
  (`factual_planet`, `long_decode_counting`, `numbers_digits`,
  `punct_contractions`), each marked `"reference": "pending"`.
- `gen_golden.py`: `PROMPT_SET_VERSION` 1.0 to 1.1, so the next
  regeneration records the new set. Existing fixtures remain bound
  to the v1.0 prompt file by SHA and stay valid for their 15
  prompts.
- `determinism_check.py`: new. Two temperature-0 runs per prompt
  against a throwaway llama-server, byte-identical token ids
  required; `--self-test` covers the comparator without a server.
- `PENDING-REFERENCES.md`: new. Why the four references are
  pending (no llama.cpp reachable from the authoring machine) and
  the exact server-side capture procedure.

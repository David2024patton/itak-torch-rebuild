# f16 KV cache for the resident session (2026-11-07)

Status: BUILT on lane/f16-kv, default OFF. The card gate below is
owed; the default does not move until it passes.

## Why

The resident session stored its per-layer K and V buffers as f32.
At full Glimmer context that is the single largest resident
allocation after the weights, and every decode step re-reads the
whole stored KV through the attention kernels. Storing K and V
as f16 halves the bytes and halves the KV read traffic in the
flash kernels, and it matches llama.cpp's default KV type
(`-ctk f16 -ctv f16` is its out-of-box cache type). The
llama-parity specs (bench/llama-parity-specs-2026-11-06.md)
sequenced this as its own gated step; this note is that step's
build record.

## Memory math (computed from the config, pinned in tests)

Rows at full context = 13 global layers x 131,072 + 39 sliding
layers x 2,048 = 1,703,936 + 79,872 = 1,783,808 rows. One row
holds K (2 KV heads x 128) + V (2 x 128) = 512 elements.

- f32: 1,783,808 x 512 x 4 B = **3,653,238,784 bytes** (~3.40 GiB)
- f16: 1,783,808 x 512 x 2 B = **1,826,619,392 bytes** (~1.70 GiB)

`full_context_kv_bytes` (k6_attention.rs) computes both from a
`GlimmerConfig`; `tests/kv_f16.rs` pins the two figures against
the real Glimmer shape. Discrepancy against the lane tasking,
stated plainly: the tasking quoted 1,826,619,392 as the f32
total. That figure is one side (K or V) in f32, equivalently
K+V in f16. The K+V f32 total is twice it. The halving claim is
exact under either reading, and the engine's number is the
config-derived one above.

## Design

Storage format: packed f16. Two values share one u32 word in
`array<u32>` storage buffers; the even element sits in the low
half, the odd element in the high half (WGSL
`pack2x16float`/`unpack2x16float` component order). No shader
extension and no `f16` WGSL type is needed: conversion goes
through the core pack/unpack builtins, so the shaders validate
under stock Naga and run anywhere the f32 forms run.

Format plumbing:

- `KvStorage { F32, F16 }` (k6_attention.rs) rides on
  `DeviceKv` (fixed at construction) and on every `LayerKv` it
  allocates. `DeviceKv::new` keeps its signature and means F32,
  so the trait path's `GpuKvState` is f32 by construction and
  untouched. `DeviceKv::new_with_storage` is the explicit form
  the resident session uses.
- `ensure_layer` allocates `capacity x kv_width x elem_bytes`;
  the geometric-growth copy is a raw byte copy and is
  layout-preserving under either format, so growth needed no
  format-specific code. Packed storage requires an even KV row
  width (two elements per word); an odd width under F16 is
  refused by name at allocation. Every served shape is even
  (head dim is even by the K9 bound; KV width multiplies it).
- Selection: `WGPU_COMPUTE_KV_F16` resolved once at backend
  construction with the codebase's fail-closed pattern: only
  the exact value `1` (trimmed) enables; unset, `0`, and
  anything else are off, and an unrecognized value is logged by
  name at construction. The resolution logs at construction
  (`kv storage config: ...`), the session logs its resolved
  format at construction, and the resident capture manifest
  records `kv_f16` beside `k21f_head`. Default OFF in this
  lane: unlike the flash and K21F flips, unset does not enable;
  the flip is a later decision gated on the card evidence
  below.

Conversion points (exactly the two the data flow has):

- **Write, once per token, in K9.** `PREP_F16_SHADER` is the
  fused preparation with the KV bindings packed. Norms,
  rotation, slot law, params, grid, and the Q output are the
  f32 form's, operation for operation. Of the three KV write
  sites, the rotation path already computes each adjacent pair
  in one lane, so that lane packs its pair directly. The
  non-rotated K path and the V path produce one element per
  lane, so the head row is staged through the workgroup `vals`
  array (the same array the rotation path uses) and the even
  lanes pack the pairs; head dim is even and at most 128, so a
  pair never straddles a head row. `PrepArgs::kv_f16` carries
  the layer's own storage flag into prepare, which selects the
  pipeline (and the diag stamp `k9_attn_prep_f16`) and takes
  the bind group layout from that pipeline, so a packed buffer
  can only bind to the packed shader.
- **Read, every step, in the flash kernels.** `FLASH_F16_SHADER`
  and `FLASH_STAGED_F16_SHADER` bind K/V as `array<u32>` and
  convert on read through shared load helpers (`kv_load_keys`
  / `kv_load_values`, spliced into both shaders from a single
  text constant so the copies cannot drift; two functions
  reading the globals directly, because Naga's validator
  rejects a pointer-to-storage function parameter's access
  mode, a defect the lane's Naga gate caught before any
  driver saw the shader). The staged twin
  unpacks each element exactly once, at the staging loads,
  into the same f32 workgroup tile the f32 form stages into:
  its workgroup-memory set is byte-identical
  (`FLASH_STAGED_LDS_BYTES` unchanged) and everything after
  staging is the f32 operation sequence. The shipped twin
  unpacks per load in its dot and reduce loops (one unpack per
  element per use, the price of not staging). `prepare_flash`
  and `prepare_flash_staged` select the twin from the layer's
  own `storage`, with distinct diag stamps
  (`k6_attn_flash_f16`, `k6_attn_flash_staged_f16`), so card
  evidence shows the f16 forms firing by name.
- **The two-pass form refuses f16 by name.** Scores/reduce
  have no f16 twin, by design: they serve the trait path,
  whose state is f32 by construction, so an f16 layer there
  can only be a wiring mistake. `prepare_scores` and
  `prepare_reduce` return a named refusal instead of binding
  a packed buffer to an f32 shader and reading garbage.

Flag off means the pre-lane engine, exactly: `DeviceKv` format
F32, the original pipelines at every prepare, byte-identical
buffers and dispatch shapes. The new pipelines are built at
construction (so a shader defect fails there, not on first
use) and never prepared against.

Scope: the resident session only. The DFlash session does NOT
share these structures: it owns per-layer `kv_k`/`kv_v` f32
buffers sized by its own `kv_capacity` config
(dflash_session.rs), read by the K17 draft kernels. Converting
it is separate work (its own write/read sites in K17), and it
is out of this lane. K5's append likewise has no f16 form: it
writes the trait path's KV, f32 by construction.

## Precision analysis (from the math)

f16 (IEEE half) carries an 11-bit significand (10 stored bits
plus the implicit leading 1): about 3.3 decimal digits.
Round-to-nearest-even conversion of a normal value errs by at
most half an ulp, a relative error of at most 2^-11 =
4.88e-4. Subnormal results (magnitudes under 2^-14) sit on a
fixed 2^-24 grid, absolute error at most 2^-25 = 3.0e-8.
Overflow needs |x| >= 65,504; post-norm K/V rows in this
engine sit near unit scale (RMSNorm output times a learned
weight), so overflow is not a live case, and values that small
that they go subnormal contribute negligibly to a dot product
either way. The host fixture measures the realized error over
a sweep, on the build VM, through the crate's own conversion
pair (`f32_to_f16_bits` / gguf's `f16_to_f32`, the host mirror
of the shaders' pack/unpack): all 63,488 representable finite
f16 values round-trip exactly, and over 200,423 arbitrary
inputs the max relative error measured 4.8804295e-4, just
under the 2^-11 bound (4.8828125e-4), with the max subnormal
absolute error at exactly 2^-25. One conversion caveat,
stated for the card run: the mirror assumes the driver's
`pack2x16float` rounds to nearest even, as WGSL specifies and
RADV implements; a driver that truncated instead would show
up in the fixture's session delta and in the identity gate,
which is part of why the gate is empirical.

How that noise reaches the logits:

1. **Scores.** A K element error of relative size up to
   4.88e-4 perturbs each attention score by at most
   sum over the head dim of |q_d| x |delta_k_d|. For
   unit-scale q and k at head dim 128 that bound is loose
   (errors are independent roundings, not aligned): the
   random-walk size is about 4.88e-4 x sqrt(128) x typical
   |q||k| product, order 1e-3 to 1e-2 on the unscaled dot,
   and the 1/sqrt(128) score scale shrinks it further.
   Softmax weights move by roughly the score perturbation
   itself (relative), so per-key weights shift by well under
   a percent in the typical case.
2. **Values.** V errors enter the attention output linearly
   through the softmax-weighted sum: relative size again
   bounded by 4.88e-4 per element, damped by the weighted
   average (no single key's error dominates unless its weight
   is near 1, in which case the output error is that value's
   own rounding, still 4.88e-4 relative).
3. **Compounding.** The perturbed attention output feeds the
   rest of the layer stack, 52 layers deep on the real model,
   each adding its own fresh KV rounding. Nothing amplifies
   systematically (norms re-normalize each block), but errors
   accumulate like a random walk rather than canceling on
   schedule; the honest expectation for finished-logit deltas
   on the real model is the 1e-2 scale, occasionally larger at
   long context where more keys vote.

Why greedy identity MIGHT hold, and why it might not: greedy
decoding only cares about the top-1 margin. The one margin
this project has measured at a failure point is instructive:
in the K21F episode the position-23 top-2 margin in finished
logits was +0.38, and a one-sided dequant corruption with a
max vocab delta of 2.04 flipped it. f16 KV noise is two-sided,
unbiased rounding with an expected finished-logit effect
around 1e-2, roughly forty times under that margin, so
identity holding on the golden prompt is the expectation, not
a hope. But margins are a distribution, not a constant: some
position in a long generation will eventually present a
near-tie (margin under the noise), and there the f16 stream
can pick the other token and diverge for good. That is the
same standing risk llama.cpp accepts with its default f16 KV,
and it is why the gate is identity+golden on the real file
rather than an argument: the question is empirical, and a
fixture cannot answer it for the real model.

The fixture in this lane (tests/kv_f16.rs, device leg) runs
the cross-fixture model in both storage modes under a shared
greedy script: top-1 agreement at every step is asserted, the
measured max logit delta is printed (on the build VM the leg
skips, no adapter enumerated, so no delta exists yet; gate
item 4 below is where the number comes from), and the
assertion ceiling is the crate's cross-backend bar of 0.5,
disclosed here as a breakage tripwire rather than a measured
bar: the card session replaces it with the measured value.
The round-trip leg's bound, by contrast, is a theorem (half
an ulp), and it is asserted tightly.

## The card gate (owed, later session)

Run on the 7900 XTX against the real Glimmer file, flag on,
with the failure-bundle wrapper:

1. **Identity + golden**, flag on: speculative identity and
   the golden 8 tokens, depths 1 and 6, at literally
   `WGPU_COMPUTE_KV_F16=1`, with the diag stamps checked for
   `k9_attn_prep_f16`, `k6_attn_flash_f16`, and
   `k6_attn_flash_staged_f16` firing (and the manifest
   carrying `kv_f16=true`). Pass = identity and golden hold;
   a divergence is reported with its stream index and the
   top-2 margin at the split, wave17-style.
2. **Long-context prefill A/B, interleaved**: the 8,202-token
   prompt wall, f32 vs f16 arms interleaved (the flash
   phantom-cost lesson: no wall claim from
   single-non-interleaved samples). The expectation is a
   modest win at long context (attention reads halve) inside
   a prefill wall that is still MMQ-dominated.
3. **Decode rate A/B, interleaved**: plain decode tok/s both
   arms; the decode stream is weight-dominated (14.89 GiB per
   token against ~1.7 GB of KV at full context, and far less
   at bench contexts), so a small or null delta is the honest
   expectation at short context, growing with context length.
4. **Fixture delta on card**: run `cargo test -p wgpu-compute
   --test kv_f16` on the server and record the printed
   f16-vs-f32 fixture delta and round-trip maxima in the flip
   note that follows this gate.

Only after 1 passes does the default-flip question open, and
it opens as its own lane with the same shape as the flash and
K21F flips (unset enables, `0` is the rollback, malformed
fails closed to off).

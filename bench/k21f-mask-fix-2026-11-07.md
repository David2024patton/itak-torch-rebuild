# K21F qc mask fix (2026-11-07)

Lane `lane/k21f-mask-fix`, based on main f57c087. The one-token
kernel fix, the test-gap closure, and the typo-class sweep. The
card retest is a separate lane after merge; nothing here ran on
the server.

## The bug

`crates/wgpu-compute/src/kernels/k21_q5k_mmv_finish.rs`, in the
generated shader header (the per-row body literal): the qc
dequant line masked its weight word with a 24-bit literal,

```wgsl
let qc = vec4<f32>(unpack4xU8(w1 & 0x0f0f0fu)) + 16.0 * bits_c;
```

where every sibling line, and the same line in
`k21_q5k_mmv.rs` and `k3_q5k_gemv.rs`, carries the 32-bit
`0x0f0f0f0fu`. One `0f` byte dropped out of the literal when
the finish variant was written as a copy of K21's text.

## Blast radius

The mask zeroes the fourth byte of `w1` before the nibble
unpack, so that byte's low nibble is always read as zero.
Per Q5_K super-block (256 elements), 16 elements lose their
entire low nibble: the qc elements at sub-blocks 4 and 6,
position `l0+3` in each affected quad. Each affected weight
dequantizes low by `nibble * d * scale` (nibble 0..15): the
error is deterministic and one-sided (always an
underestimate, never noise in both directions), which is why
it survived casual inspection of outputs while corrupting
them. Only the finish-carrying copy was wrong: plain K21
(the non-finish MMV product) always had the correct mask, so
the defect lived exactly on the resident block head route
and nowhere else. On the real file it first flipped a token
at stream position 23 of the defaults-confirmation identity
run (bench/defaults-confirmation-2026-11-07.md); the
read-only math audit against main 7940bcf then isolated it
to this line, with everything else in K21F (finish form and
position, accumulation order, partial combination,
plumbing) audited clean against K3.

## Why the VM gates could not catch it

Three gaps stacked:

1. The execution tests that would have caught it
   (tests/k21_finish.rs, the resident suites) are
   device-gated and self-skip on this GPU-less VM; the card
   protocol for the routing was still owed when it shipped.
2. The in-module shader-text test pinned only the qa line's
   mask of the four dequant lines (qa/qb/qc/qd), in both
   K21F and its K21 sibling. Three of four lines were
   unguarded text.
3. The routing test's fixture (tests/k21f_head_routing.rs)
   masked its Q5_K scale bytes with `& 0x07` and used
   d = 0.005, shrinking a dropped-nibble error far under
   its 0.5 max-abs bar.

## The fix and its companions

- The mask: `0x0f0f0fu` -> `0x0f0f0f0fu` on the qc line.
  Nothing else in the kernel changes.
- Both shader-text tests now pin ALL FOUR dequant lines
  verbatim (qa/qb/qc/qd) and carry a negative pin: the
  truncated literal `0x0f0f0fu` must never appear in the
  generated text. These are pure text tests; they run on
  the GPU-less VM.
- The routing fixture's Q5_K scale bytes are full-range
  random bytes (the k21_finish fixture's discipline),
  widening only the head tensor; the Q4_K fixture tensors
  keep their calibrated construction, and the argmax +
  max-abs assertions are unchanged. The finish (logit
  scale 0.196, tanh softcap) still compresses the logits
  the 0.5 bar reads, so honest reassociation drift does
  not widen toward the bar; the widened fixture's
  GPU-vs-CPU agreement itself is exercised by the card
  retest below, since the routing test is device-gated
  and skips here. The text pins above are the gate that
  runs everywhere.

## Demonstration: the pins bite

kernel, the extended test FAILS:

```

```

With the same typo injected into k21_q5k_mmv.rs, its
extended test FAILS the same way:

```
kernels::k21_q5k_mmv::tests::shader_specializes_the_batch_and_stages_no_weights
```

Both files were restored and the full gates re-run on the
restored tree (below).

## Typo-class sweep

Greps over the whole workspace (Rust, WGSL, GLSL .comp, Go,
shell, Python), for `0x0f0f0f` not followed by `0f`, for
truncated forms of every sibling repeating-byte family used
in dequant code (0x03, 0x0c, 0x30, 0xc0, 0x3f, 0x01), and
for the underscore-spelled Rust literals in the gguf crate:

- After the fix, every remaining `0x0f0f0fu` occurrence in
  the tree is one of this lane's own comments or negative
  test pins. Intentional, not code.
- No truncated sibling literal exists anywhere:
  `0x03030303`, `0x0c0c0c0c`, `0x30303030`, `0xc0c0c0c0`,
  `0x3f3f3f3f`, `0x01010101` appear only in full 32-bit
  form, and the gguf crate's `0x0303_0303` / `0x0f0f_0f0f`
  constants are full width.
- The distinct-literal census in wgpu-compute's kernels:
  62 x `0x0f0f0f0fu` in generated text, all other
  repeating-byte masks full width.
- No other proven-wrong literal was found, so nothing else
  was changed.
